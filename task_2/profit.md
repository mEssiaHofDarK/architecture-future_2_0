1. Клиентский домен (Customer Domain)

Единая точка правды о клиенте.
Содержит:
- основной профиль клиента;
- контакты;
- идентификаторы клиента в разных сервисах;
- статусы в программах лояльности;
- агрегированные клиентские атрибуты (но без медицины).
Почему выделен:
участвует во всех интеграциях (банк, клиники, фарма);
нужен для витрины данных.

2. Медицинский домен (Medical Core Domain)

Лечебный процесс и мед. данные — строго изолированы (при сливании в Data Lakehouse персональные и медицинские данные обезличиваются/обфусцируются).
Содержит:
- медкарты, истории болезней;
- результаты исследований;
- назначения;
- данные оборудования (диагностика, ИИ-инференс).
Особенности:
не уходит в витрину данных;
взаимодействует с другими доменами только через агрегированные/обезличенные событийные каналы;
хранится в отдельной защищённой зоне.

3. Финансовый домен (Financial Domain)

Все финансы, кроме банковских операций.
Содержит:
- платежи клиник;
- расчёты с пациентами;
- страховые взаимодействия;
- внутренняя финансовая отчётность;
- расчёты между подразделениями.
Будущие связи:
передаёт агрегированные данные в витрину;
интегрируется с банковским доменом.

4. Банковский домен (Banking Domain)

Отдельное направление с собственной регуляторикой.
Содержит:
- счета, кредиты, депозиты;
- банковские транзакции;
- скоринг;
- риск-модели.
Особенности:
не смешивается с медицинским доменом;
взаимодействует с клиентским доменом через строгие API.

5. ИИ-домен (AI)

Подготовка данных, модели, инференс, MLOps.
Содержит:
- модели диагностики;
- модели скоринга (мед + фин);
- inference API;
- фичи и фичсторы;
- pipeline-ы обучения.
Почему выносится отдельно:
подключение производителей медтехники станет проще;

6. Домены фармацевтических партнёров (Pharma Integration Domains)

Для будущей интеграции с фарм-компаниями.
Содержат:
- продукцию;
- складские позиции;
- поставки;
- контракты;
- клинические рекомендации (если будут).
Работают через:
интеграционные API;
события;
витрину данных (агрегации).

7. Домены производителей медицинского оборудования (Device / IoT Domain)

Интеграции с IoT, потоки с медоборудования.
Содержат:
- телеметрию;
- логи работы;
- результаты измерений в формате FHIR/HL7, если поддерживаются;
- данные для ИИ-инференса.
Особенности:
потоковые интеграции;
данные уходят в AI-домен

8. Операционный домен клиник (Clinic Operations Domain)

Все процессы клиники, не связанные с медицинскими данными.
Содержит:
- расписания врачей;
- очереди, приём, запись;
- инвентаризация (не мед-оборудования);
- персонал;
- ресурсы и помещения;
- управление сменами.
Будущие связи:
идёт в витрину данных;
интеграции с фармой (поставки);
интеграции с банковским доменом (оплаты).

9. Домен витрины данных (Data Products Domain)

Каждый домен публикует свои «продукты данных».
Содержит:
- агрегированные клиентские показатели;
- фин. аналитика;
- операционные данные клиник;
- показатели качества сервисов.
(Без медицинских данных.)

10. Интеграционный домен (Integration Domain)

Единое место для API, событий, маршрутизации.
Содержит:
- API-шлюз;
- сервисы авторизации и доступа к API;
- ESB/Event Bus;
- адаптеры к фарме, банку, оборудованию.
Убирает старый Camel, упрощает будущее развитие.
